# Browser acceptance checks

These checks drive the built Filedeck web app in Chromium and in Firefox with Playwright against a deterministic fake API. They run in CI on every change under `web/` (the `browser` job in `.github/workflows/ci.yml`, one run in each browser) and never call a live Filedeck API: the script intercepts every `/api/**` request in the browser and answers it from fixtures in `acceptance.mjs`, so the server only has to serve the built static files.

There is one run, no scopes. It makes these checks, in order (the names are what the output prints):

- File list: grid semantics (selected and current row, `aria-activedescendant`, file or folder in the row name); focus returns to the list after Shift+F10 then Escape, after a rename (committed and cancelled) and after creating a folder; the row context menu scrolls and every item is reachable at 1366x768, and a submenu opens inside the window.
- Keyboard: the shortcuts dialog (focus trap, focus back on its opener, URL history); Properties keys do not act on files; Tab from one panel reaches the next panel's toolbar with two and with three panels, and Alt+PageDown / Alt+PageUp switch panels; the Trash grid selects one item with Space and moves with the arrows; tooltips (hover, focus, Escape).
- Workflows: Properties tabs and chmod, no Git tab outside a repository, worktrees and the pull request diff inside the Git section, URL history and direct links (Settings, Trash, Git section), folder history, archive preview and folder-sync routes, presentation settings (32 px text without clipping, persistence, reset), copy and move to another node, saved-password renewal.
- Large and short views: a 20,000-entry listing keeps the DOM small and End and Home reach its ends; at 844x390 at least five rows are fully visible; text typed in the editor survives the window crossing the panel-width and phone thresholds.
- Editor: a file that mixes CRLF and LF shows a notice naming the ending a save writes, inside the window at 1365, 390 and 320 px and clear of the text; a file with one kind of ending shows none.
- A compare whose result reports skipped paths shows the count and the first paths in the warning area at 1365 and 390 px, and never the "Comparison done" status or the empty-state text for it.
- Address bar and Compare toolbar: every address-bar control is 44 px tall, at least 24 px wide and does not overlap another at 1365, 390 and 320 px; focusing "Edit address" with Tab does not start editing, Enter and Space do; no Compare toolbar button is clipped by its panel at 1365, 1280, 1024, 390 and 320 px; on a phone the Compare toolbar collapses to Filter, Compare by, the primary action and a More menu (at most 100 px tall, at least 8 of 40 compared rows visible at 390x844, menus reachable by keyboard and returning focus to their button).
- Sign-in: with the fake hub saying signed out (401 with `x-filedeck-auth: signed-out` from `/api/auth/me`) the sign-in screen replaces the app; axe-core passes on the password form, after a failed attempt and on the key-file form, in light and dark, with no horizontal overflow at 1365x900, 390x844 and 320x568, and the password is cleared after the failed attempt. Signed in, the header names the account and its menu offers Sign out. When the session ends while a file is being edited, signing in again as the same account brings the app back without a page load and the unsaved text is still in the editor. Every other check gets `{"auth":false}`, as from a hub with sign-in off.
- Act as root: signed in as a system administrator with the switch on, the header shows "Acting as root until HH:MM" (local time) with Stop; axe-core passes on the banner and on the open "Act as root" dialog (password form, after a failed attempt and key-file form) in light and dark, with no horizontal overflow at 1365x900, 390x844 and 320x568, and the password is cleared after the failed attempt and never stored. Stop turns the switch off and asks the hub again; turning it on with the password shows the banner; the end time, from the hub's answer or from a later `/api/auth/me`, hides it and asks the hub again. With the page's clock 20 minutes ahead of the hub, the banner still shows, names the end by the page's clock (from the hub's `asRootLeftMs`) and hides at that time. A Stop the hub does not confirm keeps the banner with the alert "Could not stop acting as root. Try again.", which passes axe in light and dark and fits at 1365x900 and 320x568. A system account that is not an administrator and a virtual account get neither the menu item nor the banner.
- Virtual account: signed in as a virtual account whose one machine has the granted folder `/srv/share` (`roots` in `/api/nodes`), with no panel in the URL, the first panel opens at `/srv/share` with "Up one folder" disabled; the sidebar shows `/srv/share` and Trash under the machine and no `/ (root)` row; no request lists `/` or asks for that machine's mounts. The address bar's first crumb shows `/srv/share`; `/` typed there stays in it; the machine's `/` typed in full is refused by the fake hub (403), and the panel then says "You have no access to this folder." with a button that opens `/srv/share`, without moving by itself. axe-core passes on both views in light and dark. Then, with two machines that each have a granted folder: a node list saved with sign-in off, one saved by another account and one in the format from before accounts (`filedeck.swr.v1`), each with a bookmark of `/`, never make the page list `/` or ask for mounts, and the foreign list is dropped from storage; in "Copy to folder", switching to the second machine opens at its granted folder with Up disabled and lists no `/`.
- Accounts: signed in as a virtual administrator, with the fake hub answering the admin routes, "Accounts…" in the account menu opens the Accounts view. "New account" with a name, a password, a run-as user and a folder picked in the folder picker sends one `POST /api/admin/accounts` with exactly that body; the hub's 409 shows its text in the alert next to the button, and a second try creates the account and opens its editor with focus on its heading; Escape with no changes goes back to the list and focuses its heading. Escape in the folder picker closes only the picker. axe-core passes on the list, the editor (also with the refusal shown) and the picker in light and dark, with no horizontal overflow at 1365x900, 390x844 and 320x568; the password never reaches a URL or the browser's storage. At 1365x900 in light and dark: the Accounts and Settings overlays fit the window and opening them does not scroll the page; axe-core passes on an existing account's editor (showing a machine and a source that are no longer configured), the "Discard changes?" dialog (focus on "Keep editing"), the delete confirm, one's own account's editor with its banner, and its "Change your own account" confirm; opening Settings closes Accounts. A system administrator gets the menu item too; an account that is not an administrator does not.
  - Tabs, sessions and system users (same check): "Accounts", "Signed in" and "System users" are a tablist (`aria-selected`, arrow keys, a tabpanel named by its tab). The Signed in tab lists the two fixture sessions, marks the caller's once and shows addresses in `<bdi>`; "End all sessions" asks first and says jobs are cancelled (and, for one's own account, that you are signed out too) and sends nothing until confirmed; "End" on the other session sends its `DELETE` and the row goes away; "End" on the caller's own session asks first. The list refreshes after 30 s while its tab is shown (fake clock) and not while another tab is shown or once the view is closed. The System users tab refuses `root` and bad names on the client, adds `alice` with Read only on a source and sends one `PUT`. The old-passwords notice shows `2`; "Forget them" asks first, sends the `DELETE`, hides the notice and focuses the list heading. axe-core passes on both tabs, the sources editor, both confirms and the notice in light and dark, with no horizontal overflow at 1365x900, 390x844 and 320x568.
- Layout: no horizontal document overflow at 1440x900, 1024x768, 768x1024, 390x844, 320x568, 844x390 and 320x256.
- axe-core with the WCAG 2.0, 2.1 and 2.2 A and AA rule tags (`wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`, `wcag22aa`) on the main view, an open context menu, an open dialog, Settings, the Trash view, the Compare view, the Markdown preview and the phone layout, each in light and dark.
- Measurements at 1365, 390 and 320 CSS pixels in light and dark: axe-core A and AA again, controls clipped by a container that cannot scroll, text-spacing overrides (WCAG 1.4.12), visible and unobscured focus, and document overflow.

The measurements also report, without failing, what the product does not claim: AAA rules from axe-core (7:1 contrast, for example) and every target smaller than 44 CSS pixels (2.5.5). They appear as `advisory` lines in the output.

A check that has found a defect the component's owner has not yet fixed is listed in the script (`expectKnownDefect`, `knownAxe`) and printed as "Known defects still present". Such a check keeps running: when the defect is fixed the run fails until the entry is removed, so the list cannot go stale.

## Running it locally

From this directory install the test dependencies and the two browsers once:

```sh
npm ci
npm run install-browser
```

Serve a built app (`npm run build` at the repository root, then start the hub with `FILEDECK_MODE=hub FILEDECK_STATIC=<repository>/web/dist PORT=<port> node server/dist/main.js`; no agent is needed) and point the script at that origin:

```sh
FILEDECK_URL=http://127.0.0.1:<port> npm run check
FILEDECK_URL=http://127.0.0.1:<port> npm run check:firefox
```

The first command uses Chromium, the second Firefox. The two runs make the same 39 checks: no check is skipped or relaxed for one browser. A check must not depend on how one engine rounds a size or scrolls a focused element; when the two browsers disagree, find out which one shows a defect a user can see and correct the product.

- `FILEDECK_URL` is required; the script contains no deployment or machine-specific address.
- `BROWSER` selects the browser: `chromium` (the default) or `firefox`. `npm run check:firefox` sets it.
- `CHROMIUM_PATH` selects a system Chromium instead of the Playwright download. Firefox always uses the Playwright download: Playwright cannot drive a system Firefox.
- `FILEDECK_EVIDENCE_DIR` is where screenshots and reports go (default `./evidence`, ignored by git). Each measurement run writes a screenshot and a JSON report there, and a failed check writes the last screenshot of each of its pages as `fail-<check>-<n>.png`. CI uploads the folder as the `browser-acceptance-evidence` artifact when the job fails.
- `FILEDECK_ONLY` runs only the checks whose name contains one of the comma-separated words, for example `FILEDECK_ONLY="focus returns,Trash"`. It is a debugging aid; CI runs everything.

A run takes two to three minutes in each browser.
