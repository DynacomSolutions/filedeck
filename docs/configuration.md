# Configuration (environment)

Agent: `FILEDECK_ROOT`, `FILEDECK_NODE`, `PORT`, `FILEDECK_TRASH_MAX_AGE_DAYS` (default 7), `FILEDECK_TRASH_MAX_PERCENT` (default 10, of the volume) and `FILEDECK_TRASH_MAX_BYTES` (default 0, off), `FILEDECK_TRASH_SWEEP_MS` (default 1 hour; trash retention: each volume's `.filedeck-trash` loses items deleted longer ago than the age limit, then its oldest items while it is over the cap; 0 turns a rule off; chart values `agent.trash.*`), `FILEDECK_MAX_UPLOAD`, `FILEDECK_MAX_EDIT`, `FILEDECK_READONLY` (comma separated absolute virtual prefixes; `//`, `/./` and a trailing slash are cleaned, and an entry that is not an absolute path stops the start; a prefix that is a link protects the place it leads to as well; where the prefix lies on a case-insensitive filesystem, such as vfat, names are matched without regard to case, which is detected by probing the prefix, so a prefix that does not exist yet or has no letters in its last name is matched exactly). One limit: a hard link that already exists outside a read-only prefix to a file inside it lets a permissions or owner change reach that file (content changes go through rename and never touch the protected file; nothing in the API creates hard links), `FILEDECK_AGENT_TOKEN`, `FILEDECK_TRANSCODE_CONCURRENCY`, `FILEDECK_THUMB_DIR`, `FILEDECK_SEARCH_CONCURRENCY` (searches that run at once, default 3; one client, as the server sees its address, may hold at most that number minus one, never fewer than two, so with the default a second tab or a second user is not refused, and a client that reads slowly cannot take every slot), `FILEDECK_WORK_DIR` (see [Archives and passwords](archives-and-passwords.md)), `FILEDECK_SANDBOX` (`auto`, `require`, `off`; see [Sandbox](security.md#sandbox)), archive, search and hash limits (see `server/src/config.ts`).

Working folders: while a copy or a move across filesystems runs, the agent builds the result in a private folder named `.filedeck-work-<run id>-<id>` (mode 0700) inside the destination folder, and moves it into place with one rename. Names that start with `.filedeck-work-`, and the name `.filedeck-work`, are reserved: they are not listed, copied or accepted as a target. A copy that is interrupted by a crash can leave such a folder behind; when a copy next uses that folder, the agent removes a leftover that holds nothing but its one built entry and has not changed for a day (24 hours), whichever process made it. A leftover that holds anything else is never touched, and can be removed by an administrator on the host.

Hub: `FILEDECK_TRUSTED_PROXIES` (reverse proxies in front of the hub whose `X-Forwarded-For` is believed, counted from the hub's side; default 0 = none: the connection's own address is used for the audit log's `ip` and the per-client search limit, and the header is ignored; chart value `hub.trustedProxies`), `NODES` (`name=http://agent:8080,...`), `FILEDECK_STATIC`, `FILEDECK_AGENT_TOKEN`, `FILEDECK_ALLOWED_HOSTS` (comma separated host names the hub answers to; any other `Host` gets 421; unset accepts any. Write the bare name, such as `files.example`, to accept every port, or `files.example:8443` to accept that port only; a name with `:80` or `:443` also matches a `Host` header without a port. The same list names the sites whose `Origin` may change state when the browser sends no `Sec-Fetch-Site`, on the request's own scheme and port), `FILEDECK_API_TOKEN` or `FILEDECK_API_TOKEN_FILE` (read-only `filedeck du` token, see [`filedeck du`](filedeck-du.md)), `FILEDECK_SOURCES` (network sources, credentials from mounted files in `FILEDECK_SOURCE_SECRETS`), `FILEDECK_BRAND`.

Sign-in (not finished, part 1 of 3; see [Sign-in and sessions](security.md#sign-in-and-sessions)): **do not set `FILEDECK_AUTH=on` on a deployment yet.** In this part the agents still do all file work as root (part 2 changes that), and every network source is open to every signed-in account (part 3 adds grants). `FILEDECK_AUTH` (hub and agents; `on` turns sign-in on, any other value or none leaves it off, and then only two things change: `GET /api/auth/me` answers `{"auth":false}`, and the web app waits for that answer before it first draws. With it on, the hub and the agent each refuse to start without `FILEDECK_AGENT_TOKEN`: they print `FILEDECK_AUTH=on needs FILEDECK_AGENT_TOKEN` and exit with status 2), `FILEDECK_ADMINS` (hub; comma separated system account names that are administrators; an administrator sees every job), `FILEDECK_BOOTSTRAP_ADMIN_FILE` (hub; a JSON file `{"name": "...", "passwordHash": "..."}` that creates the first administrator as a virtual account when the hub starts and no account has that name yet; an account that exists is never changed. The name must match `^[a-z_][a-z0-9_.-]{0,31}$` and may not be `root`; the hash must be one that `filedeck hash-password` prints, and a file that is not JSON (the hub then says only `FILEDECK_BOOTSTRAP_ADMIN_FILE is not valid JSON`, never the file's content), a file without both fields, or one with another kind of hash, stops the start; unset = none), `FILEDECK_AUTH_FILE` (hub; the SQLite file for accounts and sessions, mode 0600; default `auth.sqlite` in the folder of `FILEDECK_VAULT_FILE`; with neither set, accounts and sessions are kept in memory only and are lost when the hub stops), `FILEDECK_SESSION_IDLE_SECONDS` (hub; a session that is not used for this long ends; default 28800, 8 hours; the last use is written at most once a minute), `FILEDECK_SESSION_MAX_SECONDS` (hub; a session ends this long after sign-in, used or not; default 604800, 7 days; also the cookie's `Max-Age`), `FILEDECK_API_TOKEN_ACCOUNT` (hub; the account the `filedeck du` token acts as: the virtual account with that name if there is one, else the system account; the token then reaches only what that account reaches. With sign-in on and the setting unset or `root`, a request with the token answers 403).

HTTPS for sign-in: with `FILEDECK_AUTH=on` the hub refuses every sign-in request on plain HTTP with 403 `{"error":"sign-in needs HTTPS"}`. The hub itself serves plain HTTP only, so in a deployment HTTPS comes from a reverse proxy: set `FILEDECK_TRUSTED_PROXIES` to 1 or more and have the proxy send `X-Forwarded-Proto: https`. The hub reads only the last value of that header, and ignores the header when `FILEDECK_TRUSTED_PROXIES` is 0. With `FILEDECK_TRUSTED_PROXIES` at 0, a client whose connection comes from a loopback address (`127.0.0.0/8`, `::1`) may sign in on plain HTTP, for development on one machine. With a proxy that exemption is off, because the loopback peer is then the proxy and not the client.

Account folders of workers (sign-in on; part 2): each account's worker keeps its thumbnails in `<FILEDECK_THUMB_DIR>/accounts/u<uid>` and its index in `<FILEDECK_INDEX_DIR>/accounts/<account>` (both 0700, owned by the account; the files of the agent's own index, `index-<node>.db` and `sizes-<node>.db`, are 0600). `FILEDECK_THUMB_DIR`, `FILEDECK_INDEX_DIR` and their `accounts` folders must belong to the agent's user (root) and must not be writable by group or others; when the agent runs as root and finds one of the two folders root's but writable by others (an empty volume is 0777), it makes it 0755 at start and logs one line. A folder that belongs to another user is refused: requests answer 503 `{"error":"worker folders are not safe"}` and the log names the folder, its owner and its mode. Every folder above them must be passable by the accounts (the search bit for others): if it is not, the worker stops at start with the log line `worker: cannot use its index folder <path> (EACCES): the account must be able to pass through every folder above it`, and requests answer 503 `{"error":"worker failed to start"}`. Virtual accounts need Landlock ABI 3 or newer (Linux 6.2); on an older kernel their requests answer 503 `{"error":"virtual accounts need Landlock on this machine"}`, and the agent logs the ABI it found at start. A virtual account's worker can reach only its grants, so its archive jobs stage in the worker's own temporary folder (TMPDIR) and copy the result into place, instead of renaming it from `.filedeck-work` on the volume: that folder needs room for the largest archive.

`filedeck hash-password` reads one line from standard input (on a terminal it asks `Password:` and does not show what you type) and prints a hash in the form `scrypt$15$8$1$<salt>$<hash>`, for `FILEDECK_BOOTSTRAP_ADMIN_FILE`. An empty password is refused (exit status 2). For example: `filedeck hash-password` on a terminal, or `printf '%s\n' "$PASSWORD" | filedeck hash-password` from a script.

Connection timeouts (fixed, not settings): the hub and the agent keep an idle HTTP connection open for 65 seconds, and the hub's client drops an idle pooled connection after 30 seconds (sooner when the server announces a shorter keep-alive time), so the server is not the side that closes a connection the client is about to reuse. The header timeout is 70 seconds, above the keep-alive time as Node requires; a connection that is slow to send its request headers can therefore stay open for about 100 seconds instead of about 60. The hub repeats a hub-to-agent read (GET, HEAD) once on a new connection if a pooled one was closed under it; it never repeats a request that changes something.

`FILEDECK_BRAND` is JSON: `{"name","title","icon","css","themeKey"}`. Unset, the page says "Filedeck", has no logo and no header links (the header never carries logos or links to other sites; only the name, selection actions, Compare panels, theme and help).
