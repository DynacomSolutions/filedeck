# Configuration (environment)

Agent: `FILEDECK_ROOT`, `FILEDECK_NODE`, `PORT`, `FILEDECK_TRASH_MAX_AGE_DAYS` (default 7), `FILEDECK_TRASH_MAX_PERCENT` (default 10, of the volume) and `FILEDECK_TRASH_MAX_BYTES` (default 0, off), `FILEDECK_TRASH_SWEEP_MS` (default 1 hour; trash retention: each volume's `.filedeck-trash` loses items deleted longer ago than the age limit, then its oldest items while it is over the cap; 0 turns a rule off; chart values `agent.trash.*`), `FILEDECK_MAX_UPLOAD`, `FILEDECK_MAX_EDIT`, `FILEDECK_READONLY` (comma separated absolute virtual prefixes; `//`, `/./` and a trailing slash are cleaned, and an entry that is not an absolute path stops the start; a prefix that is a link protects the place it leads to as well; where the prefix lies on a case-insensitive filesystem, such as vfat, names are matched without regard to case, which is detected by probing the prefix, so a prefix that does not exist yet or has no letters in its last name is matched exactly). One limit: a hard link that already exists outside a read-only prefix to a file inside it lets a permissions or owner change reach that file (content changes go through rename and never touch the protected file; nothing in the API creates hard links), `FILEDECK_AGENT_TOKEN`, `FILEDECK_TRANSCODE_CONCURRENCY`, `FILEDECK_THUMB_DIR`, `FILEDECK_SEARCH_CONCURRENCY` (searches that run at once, default 3; one client, as the server sees its address, may hold at most that number minus one, never fewer than two, so with the default a second tab or a second user is not refused, and a client that reads slowly cannot take every slot), `FILEDECK_WORK_DIR` (see [Archives and passwords](archives-and-passwords.md)), `FILEDECK_SANDBOX` (`auto`, `require`, `off`; see [Sandbox](security.md#sandbox)), archive, search and hash limits (see `server/src/config.ts`).

Working folders: while a copy or a move across filesystems runs, the agent builds the result in a private folder named `.filedeck-work-<run id>-<id>` (mode 0700) inside the destination folder, and moves it into place with one rename. Names that start with `.filedeck-work-`, and the name `.filedeck-work`, are reserved: they are not listed, copied or accepted as a target. A copy that is interrupted by a crash can leave such a folder behind; when a copy next uses that folder, the agent removes a leftover that holds nothing but its one built entry and has not changed for a day (24 hours), whichever process made it. A leftover that holds anything else is never touched, and can be removed by an administrator on the host.

Hub: `FILEDECK_TRUSTED_PROXIES` (reverse proxies in front of the hub whose `X-Forwarded-For` is believed, counted from the hub's side; default 0 = none: the connection's own address is used for the audit log's `ip` and the per-client search limit, and the header is ignored; chart value `hub.trustedProxies`), `NODES` (`name=http://agent:8080,...`), `FILEDECK_STATIC`, `FILEDECK_AGENT_TOKEN`, `FILEDECK_ALLOWED_HOSTS` (comma separated host names the hub answers to; any other `Host` gets 421; unset accepts any. Write the bare name, such as `files.example`, to accept every port, or `files.example:8443` to accept that port only; a name with `:80` or `:443` also matches a `Host` header without a port. The same list names the sites whose `Origin` may change state when the browser sends no `Sec-Fetch-Site`, on the request's own scheme and port), `FILEDECK_API_TOKEN` or `FILEDECK_API_TOKEN_FILE` (read-only `filedeck du` token, see [`filedeck du`](filedeck-du.md)), `FILEDECK_SOURCES` (network sources, credentials from mounted files in `FILEDECK_SOURCE_SECRETS`), `FILEDECK_BRAND`.

Sign-in (see [Sign-in and sessions](security.md#sign-in-and-sessions) and [Administrators](security.md#administrators)): accounts are managed in the Accounts view, which administrators open from the account menu; `FILEDECK_ADMINS` and `FILEDECK_BOOTSTRAP_ADMIN_FILE` only name the first administrators. System accounts sign in through the agents, and a network source is open only to an administrator or to an account with a grant for it. With it on, the agents run every signed-in request in a worker process as that account (see [Workers on the agents](security.md#workers-on-the-agents)). `FILEDECK_AUTH` (hub and agents; `on` turns sign-in on, any other value or none leaves it off, and then these are the only changes from a version without sign-in: `GET /api/auth/me` answers `{"auth":false}`; the web app waits for that answer before it first draws; the agent keeps its own index and folder-size files (`index-<node>.db`, `sizes-<node>.db` or its later generation `sizes-<node>.db.gen<N>`, and their `-wal`, `-shm` and journal files) at mode 0600, and changes those an older version left to 0600; a trash item's `meta.json` is read only when it is a regular file of at most 1 MiB and not a link (else the item is listed under its id, and it can be deleted but not restored); a value of `FILEDECK_MAX_WORKERS` or `FILEDECK_WORKER_IDLE_SECONDS` that is not a whole number of at least 1 stops the start; the trash also lists the account folders (`u<uid>`, `v-<name>`) that sign-in left on a volume (see [Trash with sign-in on](security.md#sign-in-and-sessions)); every path under `/api/admin/` answers 404 `{"error":"not found"}` (JSON, never the web app); and a request under `/api/admin/` is written to the audit log whatever its method, GET, HEAD and OPTIONS too (elsewhere only requests that change something are). With it on, the hub and the agent each refuse to start without `FILEDECK_AGENT_TOKEN`: they print `FILEDECK_AUTH=on needs FILEDECK_AGENT_TOKEN` and exit with status 2), `FILEDECK_ADMINS` (hub; comma separated system account names that are administrators; an administrator sees every job, uses every network source and opens the Accounts view; the list can be changed only here, not in the Accounts view), `FILEDECK_BOOTSTRAP_ADMIN_FILE` (hub; a JSON file `{"name": "...", "passwordHash": "..."}` that creates the first administrator as a virtual account when the hub starts and no account has that name yet; an account that exists is never changed. The file is used once: the auth database records that it was used (also when an account of that name existed already), and from then on the hub does not read it, and logs at each start that it is set but was already used. A first administrator deleted later is therefore not made again. Use it only for the first administrator: sign in as that account, make the others in the Accounts view, and then remove the file and the setting. The name must match `^[a-z_][a-z0-9_.-]{0,31}$` and may not be `root`; the hash must be one that `filedeck hash-password` prints, and a file that is not JSON (the hub then says only `FILEDECK_BOOTSTRAP_ADMIN_FILE is not valid JSON`, never the file's content), a file without both fields, or one with another kind of hash, stops the start; unset = none), `FILEDECK_AUTH_FILE` (hub; the SQLite file for accounts and sessions, mode 0600; default `auth.sqlite` in the folder of `FILEDECK_VAULT_FILE`; with neither set, accounts and sessions are kept in memory only and are lost when the hub stops), `FILEDECK_SESSION_IDLE_SECONDS` (hub; a session that is not used for this long ends; default 28800, 8 hours; the last use is written at most once a minute), `FILEDECK_SESSION_MAX_SECONDS` (hub; a session ends this long after sign-in, used or not; default 604800, 7 days; also the cookie's `Max-Age`), `FILEDECK_API_TOKEN_ACCOUNT` (hub; the account the `filedeck du` token acts as: the virtual account with that name if there is one, else the system account; the token then reaches only what that account reaches. With sign-in on and the setting unset or `root`, a request with the token answers 403).

HTTPS for sign-in: with `FILEDECK_AUTH=on` the hub refuses every sign-in request on plain HTTP with 403 `{"error":"sign-in needs HTTPS"}`. The hub itself serves plain HTTP only, so in a deployment HTTPS comes from a reverse proxy: set `FILEDECK_TRUSTED_PROXIES` to 1 or more and have the proxy send `X-Forwarded-Proto: https`. The hub reads only the last value of that header, and ignores the header when `FILEDECK_TRUSTED_PROXIES` is 0. With `FILEDECK_TRUSTED_PROXIES` at 0, a client whose connection comes from a loopback address (`127.0.0.0/8`, `::1`) may sign in on plain HTTP, for development on one machine. With a proxy that exemption is off, because the loopback peer is then the proxy and not the client.

System sign-in (sign-in on): `FILEDECK_AUTH_NODES` (hub; comma separated machine names asked, in this order, to check a system account's password or key; empty = the order of `NODES`; the first machine that accepts ends the search; chart value `auth.authNodes`) and `FILEDECK_PAM_SERVICE` (agent; default `filedeck`; the PAM service the agent's `filedeck-pam` uses, which is the file `/etc/pam.d/<name>` on the machine and which you must install yourself, see [Install](install.md#system-sign-in-pam); chart value `auth.pamService`). The same chart values `auth.admins`, `auth.bootstrapAdmin` (a Secret and key mounted read-only on the hub, for `FILEDECK_BOOTSTRAP_ADMIN_FILE`), `auth.session.*` and `auth.apiTokenAccount` set the other sign-in names above.

Tailscale sign-in (hub; see [Tailscale sign-in](security.md#tailscale-sign-in); all four are off by default and are read only when `FILEDECK_AUTH=on`): `FILEDECK_TAILSCALE_SOCKET` (the path of tailscaled's LocalAPI socket; turns the socket source on, which gives logins and tags; chart value `auth.tailscale.socket`, set for you by the sidecar), `FILEDECK_TAILSCALE_HEADERS` (`on` turns the headers source on, which reads the Tailscale Serve identity headers and gives logins only; any other value leaves it off; ignored when the socket is set; chart value `auth.tailscale.headers`) and `FILEDECK_TAILSCALE_PROXIES` (comma separated IP addresses and CIDR ranges, for example `127.0.0.1/32,::1/128`: the proxies that carry only tailnet traffic to the hub. A request has a tailnet identity only when its connection comes from one of them. It is separate from `FILEDECK_TRUSTED_PROXIES`, has no default, and is needed when a source is on; chart value `auth.tailscale.proxies`, to which the sidecar adds the two loopback entries). `FILEDECK_TAILSCALE_LISTEN` (`<IPv4>:<port>` or `[<IPv6>]:<port>`, for example `127.0.0.2:8081`: a second listener of the hub. When it is set, an identity is read only on connections it accepts, still from a listed proxy; the ordinary port never gives one. Needed when a loopback address is listed, because tailscaled in userspace mode and any local process reach the hub from loopback; chart value `auth.tailscale.listen`, set by the sidecar to `127.0.0.2:<listenPort>`). A listed proxy must carry no public traffic. At start the hub refuses these: a loopback entry in `FILEDECK_TAILSCALE_PROXIES` with a source and no `FILEDECK_TAILSCALE_LISTEN` stops the start and names `FILEDECK_TAILSCALE_LISTEN`; a listen value that is not an address and a port, is `127.0.0.1`, `::1` or an unspecified address, or has the hub's port is an error; an entry of `FILEDECK_TAILSCALE_PROXIES` that is not an IP address or range stops the start with `FILEDECK_TAILSCALE_PROXIES: "<entry>" is not an IP address or range`, and a source with an empty list stops it with `FILEDECK_TAILSCALE_PROXIES is needed when FILEDECK_TAILSCALE_SOCKET or FILEDECK_TAILSCALE_HEADERS is set`. It logs one line, `tailscale: sign-in with Tailscale through the <socket or headers> source, from <proxies>` (never the socket path), `tailscale: identities are read only on connections to <address>` when the listener is set, and, when both sources are set, `tailscale: FILEDECK_TAILSCALE_SOCKET is set, so FILEDECK_TAILSCALE_HEADERS is ignored`. With sign-in off, a set value gives one line, `tailscale: sign-in is off, so FILEDECK_TAILSCALE_* is ignored`, and nothing else; the two routes `/api/auth/tailnet` and `/api/auth/login-tailscale` do not exist. With the socket source, while tailscaled does not answer, the hub logs `tailnet: the tailscaled socket did not answer (<reason>)` at most once a minute. Links that administrators make count for the last administrator only while a source is on that can use them (see [Tailscale sign-in](security.md#tailscale-sign-in)), so turning a source off can leave a hub with no virtual administrator who can sign in: add a system user to `FILEDECK_ADMINS` and restart, or turn sign-in off for a moment.

Workers (agent, sign-in on): `FILEDECK_MAX_WORKERS` (default 6; workers that run at once on one agent; when a new account needs one, the least recently used idle worker is stopped, and when all are busy the answer is 503 with `Retry-After: 5`; chart value `auth.workers.max`), `FILEDECK_WORKER_IDLE_SECONDS` (default 600; a worker without a request in flight, an open stream or a running job for this long exits; chart value `auth.workers.idleSeconds`). Each worker has a heap of at most 96 MiB, so allow for that in the agent's memory limit (the chart raises it to `auth.agentMemoryLimit`, 1Gi by default). For both settings an empty value means the default, and any other value that is not a whole number of at least 1 stops the start with `<NAME> must be a whole number of at least 1, not "<value>"`. `FILEDECK_HOST_HELPERS` (agent; the folder that holds the account lookup helper `filedeck-id`; unset = the image's `/usr/local/lib/filedeck/host`, else the one `npm run build` makes beside the code. The helper is run from that folder by its descriptor inside the machine's root, so nothing is copied to the machine. When the folder has no `filedeck-id`, or it cannot run on the machine, the agent logs `system accounts: host lookup unavailable (<reason>); only local /etc/passwd accounts resolve, and system sign-in is refused` and reads accounts only from the machine's `/etc/passwd` and `/etc/group`. Leave it unset in the image.) `FILEDECK_PAM_SERVICE` (agent, sign-in on; default `filedeck`): the PAM service that checks system users' passwords, `/etc/pam.d/<name>` on the machine. The check runs in the host helper `filedeck-pam` from the same folder, inside the machine's root, once per attempt; the password reaches it only on its input pipe. Only one password prompt is supported: a stack that asks a second question (a one-time code) or a visible one fails the attempt, and the agent logs `pam: the service asked more than one question; only one password prompt is supported`. A missing service file, a missing `libpam.so.0` or a missing `filedeck-pam` makes system sign-in unavailable on that machine, and the agent logs `system sign-in: unavailable (<reason>)` at start or `pam: unavailable (<reason>)` per attempt. Key sign-in for system accounts uses only `<home>/.ssh/authorized_keys` on the machine, read as the user (not `authorized_keys2`, and not a path set by sshd's `AuthorizedKeysFile`); a key line with options never counts, and a file that cannot be read gives a failed sign-in and the agent line `keys: the authorized_keys of <name> could not be read (<reason>)`. `FILEDECK_AUTH_NODES` (hub, sign-in on; comma-separated node names): the machines asked to check a system user's password or key, in this order; unset = the order of `NODES`. A name that is not in `NODES` stops the start with `FILEDECK_AUTH_NODES names an unknown node: <name>`. The first machine that says the password or key is right signs the user in, and one that says it is wrong ends the attempt; a machine where the name has uid 0, gid 0 or group 0 ends the attempt in the same way (so does no machine after it in the order); a machine that does not know the name, cannot check, does not answer within 15 seconds or cannot be reached is passed over, and the whole attempt ends after 20 seconds. `FILEDECK_AUTH_NODES` does not decide which machines a system user sees: that is every machine in `NODES` where the account exists (asked of each machine at sign-in, kept for 5 minutes; a machine that does not answer stays listed; see [Sign-in and sessions](security.md#sign-in-and-sessions)).

Index folder on the machine (agent): the chart mounts a host folder at `/var/lib/filedeck` and sets `FILEDECK_INDEX_DIR=/var/lib/filedeck/index`. The chart value `agent.indexHostPath` (default `/var/lib/filedeck`) chooses the host folder for all agents, and `nodes[].indexHostPath` chooses it for one agent, for example `/home/filedeck` on a machine whose root partition is small. The folder is created on first start. The path in the container and `FILEDECK_INDEX_DIR` do not change. Moving the folder starts with an empty index, which the agent rebuilds.

Account folders of workers (sign-in on; part 2): each account's worker keeps its thumbnails in `<FILEDECK_THUMB_DIR>/accounts/u<uid>` and its index in `<FILEDECK_INDEX_DIR>/accounts/<account>` (both 0700, owned by the account; the files of the agent's own index, `index-<node>.db` and `sizes-<node>.db`, are 0600). Every account with one uid (a system account, and each virtual account that runs as it) shares that thumbnail folder. Each account's thumbnail cache holds at most `FILEDECK_THUMB_CACHE_MAX` (default 256 MiB) divided by twice `FILEDECK_MAX_WORKERS` (stopped workers may still be exiting while new ones run), and never less than 1 MiB. Once no worker runs as a uid, the agent empties its thumbnail cache, as the account (root never walks it), and at start it empties every cache that an earlier agent left; so all caches together stay within `FILEDECK_THUMB_CACHE_MAX` (unless the 1 MiB floor is above the share). `FILEDECK_THUMB_DIR`, `FILEDECK_INDEX_DIR` and their `accounts` folders must belong to the agent's user (root) and must not be writable by group or others; when the agent runs as root and finds one of the two folders root's but writable by others (an empty volume is 0777), it makes it 0755 at start and logs one line. A shared folder with the sticky bit, such as `/tmp`, is never changed: the agent logs `<folder> is mode 1777 (a shared folder); it is left as it is, and workers are refused until FILEDECK_THUMB_DIR or FILEDECK_INDEX_DIR names a folder of its own`, and every worker start answers 503 `{"error":"worker folders are not safe"}`. So set `FILEDECK_THUMB_DIR` (and `FILEDECK_INDEX_DIR`, when set) to a folder only Filedeck uses, never to `/tmp` itself; the chart uses its own volume at `/var/cache/filedeck` for thumbnails and `/var/lib/filedeck/index` on the node for the index, which need no change. Each worker's temporary folder (its `TMPDIR` and `HOME`) is its own 0700 folder in a workers' area, `filedeck-workers-<pid>-<random>` (root's, 0711), in the agent's temporary folder (`TMPDIR`, else `/tmp`). That folder must be root's, and when others may write to it, it must have the sticky bit, so that nobody else can move the area. At start with sign-in on, when the folder is root's, open to others and without the sticky bit (the chart's `/tmp` is an empty volume, 0777), the agent sets the sticky bit and logs `<folder> was mode 777 (others could move the workers' folders in it); made 1777 (sticky)`; so the chart's `/tmp` needs no change either. A temporary folder that is not root's is refused: the agent logs `workers are refused: the temporary folder <folder> has owner <uid> and mode <mode>; ...` and every worker start answers 503 `{"error":"worker folders are not safe"}`. A worker whose temporary folder is not its own 0700 folder, or has a link on its path, stops at start with the log line `worker: its temporary folder "<path>" is not its own 0700 folder (<reason>); stopped`, and requests answer 503 `{"error":"worker failed to start"}`. The agent removes its area when it stops; an area that a killed agent left is removed at the next start (the accounts' folders in it are emptied as the accounts). Unset, `FILEDECK_THUMB_DIR` is `filedeck-thumbs` in the temporary folder, which is its own folder too. A folder that belongs to another user is refused: requests answer 503 `{"error":"worker folders are not safe"}` and the log names the folder, its owner and its mode. Every folder above them must be passable by the accounts (the search bit for others): if it is not, the worker stops at start with the log line `worker: cannot use its index folder <path> (EACCES): the account must be able to pass through every folder above it`, and requests answer 503 `{"error":"worker failed to start"}`. Virtual accounts need Landlock ABI 3 or newer (Linux 6.2); on an older kernel their requests answer 503 `{"error":"virtual accounts need Landlock on this machine"}`, and the agent logs the ABI it found at start. A virtual account's worker can reach only its grants, so its archive jobs stage in the worker's own temporary folder (TMPDIR) and copy the result into place, instead of renaming it from `.filedeck-work` on the volume: that folder needs room for the largest archive.

`filedeck hash-password` reads one line from standard input (on a terminal it asks `Password:` and does not show what you type) and prints a hash in the form `scrypt$15$8$1$<salt>$<hash>`, for `FILEDECK_BOOTSTRAP_ADMIN_FILE`. An empty password is refused (exit status 2). For example: `filedeck hash-password` on a terminal, or `printf '%s\n' "$PASSWORD" | filedeck hash-password` from a script.

Connection timeouts (fixed, not settings): the hub and the agent keep an idle HTTP connection open for 65 seconds, and the hub's client drops an idle pooled connection after 30 seconds (sooner when the server announces a shorter keep-alive time), so the server is not the side that closes a connection the client is about to reuse. The header timeout is 70 seconds, above the keep-alive time as Node requires; a connection that is slow to send its request headers can therefore stay open for about 100 seconds instead of about 60. The hub repeats a hub-to-agent read (GET, HEAD) once on a new connection if a pooled one was closed under it; it never repeats a request that changes something.

Job notifications (Web Push, hub): with the Settings switch on, the browser gives the hub a push subscription, which the hub keeps with the account and the session it was made in (sign-in off: one shared list). Every 15 seconds the hub lists each subscribed account's jobs as that account (its hub operations, its compares and each machine's jobs, through the same checks as the account's own requests) and sends one push for each job started from the app that finished or failed after the subscription was made, at most a day back; each subscription gets a job end once, also with two hub pods (the store records it before the send, and gives it back when the send fails, so the next pass tries again). Cancelled jobs are never sent. The payload is the job title, the outcome and the first line of an error, encrypted for the browser (RFC 8291) and signed with the hub's VAPID key (RFC 8292). A subscription ends with its session (sign-out, the absolute limit, ended by an administrator), with any change to its account, and when the push service answers 404 or 410. A session that only goes idle (the app is closed) keeps its subscriptions until its absolute limit (`FILEDECK_SESSION_MAX_SECONDS`): notifications while the app is closed are the point, and a push carries no access. The hub posts only to `https` addresses on the default port of the browsers' push services (`fcm.googleapis.com`, `updates.push.services.mozilla.com`, hosts under `push.apple.com` and `notify.windows.com`), so the hub needs outbound HTTPS to them. `FILEDECK_PUSH` (hub; `off` turns it off: `/api/push/*` answers 404 and the app keeps to notifications while a tab is open), `FILEDECK_PUSH_FILE` (hub; the SQLite file for the key pair, the subscriptions and the sent marks, mode 0600; default `push.sqlite` in the folder of `FILEDECK_VAULT_FILE`; with neither set they are kept in memory and a restart makes a new key, so browsers subscribe again at their next start), `FILEDECK_PUSH_SUBJECT` (hub; the contact the push services see in the VAPID token, a `mailto:` or `https:` URL; default the project's address), `FILEDECK_PUSH_HOSTS` (hub; comma separated extra push service hosts, for a self-hosted push service). The key pair is made by the hub on first use; there is nothing to set up.

`FILEDECK_BRAND` is JSON: `{"name","title","icon","css","themeKey"}`. Unset, the page says "Filedeck", has no logo and no header links (the header never carries logos or links to other sites; only the name, selection actions, Compare panels, theme and help). The hub also writes `name` into the installed app's name under its icon (the manifest's `short_name` and the iOS home-screen title) and `title` into the manifest's `name`; the icons stay the bundled ones.

## Change events

Agent settings. See [Change events](change-events.md).

- `FILEDECK_HOLDERS`: the eBPF helper that keeps the table of which process holds which file or folder, for example `/usr/local/bin/filedeck-holders`. Empty means off. The chart sets it with `agent.holders.ebpf`. `FILEDECK_HOLDERS_RING_MB` is the size of its ring buffer in MiB (a power of two from 1 to 256, default 16). See [Holders](holders.md).
- `FILEDECK_FANWATCH`: the fanotify helper, for example `/usr/local/bin/filedeck-fanwatch`. Empty means off. The chart sets it with `agent.fanotify.enabled`. The helper has one setting of its own, in its environment: `FILEDECK_FANWATCH_CACHE` is the number of folder handles in its path cache (default 16384, 0 means no cache).
- `FILEDECK_SIZE_COMMIT_MS` (default 30000): how often the folder-size store follows the change events. The agent keeps the folders that changed in memory, merges them per folder, and writes and re-reads them together once per interval. A folder size can be as old as the interval. At shutdown the open interval is handed to the store. `0` gives the old behaviour (every 250 ms). Chart value: `agent.sizeStore.commitMs`.
- `FILEDECK_SIZE_DIRTY_MAX` (default 2000): the most changed folders that the agent holds in memory for one interval. Above it, folders that share a subtree become one stale mark of that subtree, and the next read of the subtree scans it again.
- `FILEDECK_SIZE_EXCLUDE` (default `pg_wal,node_modules,target,.git/objects,cargo-target`): a comma list of folder names or globs. A change inside such a folder, at any depth, causes no write to the size store. A run of names such as `.git/objects` must follow each other. The size of an excluded folder comes from the scheduled scans only, so it can show the last scan. The change event stream, its journal and the socket still get every event. An empty value turns excludes off. Chart value: `agent.sizeStore.exclude`.
- Size store metrics: `filedeck_size_commits_total`, `filedeck_size_commit_dirty_paths_total` and `_last`, `filedeck_size_commit_collapsed_total`, `filedeck_size_excluded_events_total`, `filedeck_size_commit_duration_seconds` (sum and count) and `filedeck_size_store_write_transactions_total`.
- `FILEDECK_EVENTS_SOCKET`: the path of the Unix socket for other programs on the machine. Empty means off. The agent makes its folder with mode 0750 and the socket with mode 0660. The path has at most 100 bytes. Chart values: `agent.events.socket.*`.
- `FILEDECK_EVENTS_SOCKET_GROUP`: the group of the folder and the socket, a name or a number. A number is safest, because a name is looked up in `/etc/group` of the container.
- `FILEDECK_EVENTS_JOURNAL_BYTES` (default 2 GiB, 0 means the journal stays in memory) and `FILEDECK_EVENTS_JOURNAL_HOURS` (default 24): the journal keeps the smaller of the two limits. It is in `changes-<node>/` inside `FILEDECK_INDEX_DIR`. Chart values: `agent.events.journal.*`.
- `FILEDECK_EVENTS_LABELS`: label templates, separated by line feeds, semicolons or commas. Example: `/srv/repos/{org}/{repo}`. The agent logs a bad template and makes no label. Chart value: `agent.events.labels`.
- `FILEDECK_INDEX_WATCHES`: the folders that the compare index keeps under change watch (default 32768). With the fanotify helper on, a watch is a table entry in memory that the event bus feeds, not a kernel watch. For a folder that no kernel watcher covers, it is an `fs.watch` of the folder.

Hub setting:

- `FILEDECK_API_TOKEN_SCOPES`: what the token of `FILEDECK_API_TOKEN` may read, separated by commas. `du` is folder sizes, `changes` is the change event stream and `holders` is the table of who holds a path. The default is `du`. Chart value: `apiToken.scopes`.
