# Installable app (PWA) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the Filedeck web app an installable PWA with offline shell, update prompt, job notifications and Install app.

**Architecture:** Hand-written service worker (`web/src/sw.ts`) emitted as `/sw.js` by a small Vite plugin that injects the precache
list and version; request policy in a pure module (`web/src/swPolicy.ts`). Page side in `web/src/pwa.ts` (registration, update
state, install prompt, notifications) with a pure decision module `web/src/jobNotify.ts`. Hub renders the manifest with the brand.

**Tech Stack:** React 19, Vite 8 (rolldown), Hono hub, node:test, Playwright.

**Spec:** docs/superpowers/specs/2026-11-18-pwa-design.md

## Global Constraints

- The service worker never calls `respondWith` for `/api` or anything under `/api/`, for non-GET, or for another origin.
- Notification permission is requested only from the Settings switch click handler.
- Colours: dark theme `#151518` (theme), `#0c0c0e` (background); light theme `#ffffff`, `#e9ebef`.
- No infrastructure names in the repo. British English in user-facing copy.
- `npm test -w web`, `npm run typecheck`, `npm run check:neutral`, browser suite in Chromium and Firefox all pass.

## Review Focus

- A deep link (`/?panes=...`) opened offline gets the stored shell, not a browser error page (test in swPolicy: navigation → `shell`).
- `/api` itself (no trailing slash) and `/api?x` are not handled (swPolicy test).
- A user who denies permission sees the switch off with an explanation, not an on switch that never notifies (jobNotify/settings test).
- Two tabs open when an update lands: the tab that did not click is not reloaded silently (pwa update state test).
- Cancelled jobs never notify; several jobs ending together give one notification (jobNotify test).
