# WCAG 2.2 audit (source review and scoped browser checks, updated 12 November 2026)

This is a criterion-by-criterion source audit with scoped browser acceptance evidence, not a conformance claim. WCAG 2.2 AAA conformance requires every applicable A, AA, and AAA criterion across complete pages and processes. See the [W3C WCAG 2.2 Recommendation](https://www.w3.org/TR/WCAG22/). Each statement below says what it rests on: **source** (a reading of the code on `main`) or **browser** (a check in `web/test/browser/acceptance.mjs`, which runs in CI against a deterministic fake API in Chromium; see "Scoped browser validation"). Browser checks cover only the profiles and workflows recorded below; assistive-technology combinations, real devices, real browser zoom, other browsers, deployment overrides, custom colour combinations, node configurations and arbitrary user-provided content remain outside that evidence. `Unverified` means the available source and scoped runtime evidence do not prove the full criterion; it is not a pass. `N/A` is scoped to the current Filedeck interface and must be revisited if the product adds the described content or flow.

## Findings and changes

- `Tooltip.tsx`: tooltip remains pointer-hoverable, closes on Escape, and stays associated with its trigger. This addresses the prior immediate close/pointer-events failure against 1.4.13.
- `ContextMenu.tsx`: enabled menu items receive real DOM focus with roving tab stops; arrows, Home/End, type-ahead and nested menu navigation operate on the focused item (source). Browser: Escape from a menu opened with Shift+F10 returns focus to the file list, and from the New menu to the New button; at 1366x768 the row menu (20 items, taller than the window) is kept inside the window and scrolls, every enabled item stays reachable with the arrow keys, and a submenu opens inside the window. Focus also returns to the list after a rename (committed or cancelled) and after creating a folder.
- `ArchiveDialog.tsx`: the dialog form itself carries the dialog semantics, initially focuses its first available control (or dialog), traps Tab, and returns focus on close.
- `Columns.tsx`: sort headers are buttons and expose the current sort via `aria-sort` (source).
- `FilePanel.tsx`: the file list. The list view is an ARIA `grid` (multi-selectable, `aria-rowcount`, rows with `aria-rowindex` and `aria-selected`, the current row named by `aria-activedescendant`); the grid view is a `listbox` of `option` tiles (`aria-setsize`, `aria-posinset`, `aria-selected`). Each row or tile has a name that begins "File", "Folder" or "Link" (the icon is hidden from assistive technology). Only the rows near the viewport are in the DOM (the grid still reports the full count). Tab follows the normal page order; Alt+PageDown and Alt+PageUp move to the next and previous panel's list. Browser: the list view exposes the selected and the current row and the "File," / "Folder," names; a 20,000-entry listing renders fewer than 400 rows and End and Home reach its ends; Tab from the last control of panel one reaches panel two's toolbar (after the resize handle between them, which is a Tab stop of its own) with two and with three panels, and Alt+PageDown / Alt+PageUp switch panels. The tile (listbox) markup is source only, and how screen readers announce either view is unverified. Panel tabs no longer exist; `Properties.tsx`, the Trash volumes and the Markdown and sheet views use `tablist` with native button tabs, selected state, labelled tabpanels and arrow/Home/End keys (source; the Properties keys are exercised in the browser check).
- `Compare.tsx`: aligned comparison rows expose row/cell relationships and the focused grid names its active row (source). Browser: the Compare view has no axe-core A or AA violation in light or dark.
- `AddressBar.tsx`: recent/folder popups expose menu/menuitem semantics, move DOM focus with arrow/Home/End keys, and Escape/Left returns focus to the opener.
- `Dialogs.tsx` and `FilePanel.tsx`: invalid name/link/create fields reference their inline error text; new errors are announced. `Jobs.tsx` keeps interactive job controls outside its concise live-status announcement.
- `Shortcuts.tsx`: the help dialog keeps keyboard focus within its controls and returns it on close.
- `AccessibilityChrome.tsx` and `accessibility.css` provide the skip link, main landmark focus target, contextual document title, reduced-motion overrides and bundled theme tokens (source). Measured in the browser from the computed theme tokens in both themes: muted text is 7.09:1 or better on the three bundled surfaces in light (8.86:1 on the page surface) and 7.36:1 or better in dark; the control boundary is 4.88 to 6.10:1 in light and 3.42 to 4.30:1 in dark (3:1 or better on every surface, which is what 1.4.11 asks; the earlier "at least 5.54:1" held for light only); the focus ring and the selection mark are 9.65 to 12.06:1 in light and 8.45 to 10.64:1 in dark. These numbers do not establish contrast for runtime custom colours, deployment overrides, overlays or every state. `PresentationSettings.tsx` and `presentation.css` provide foreground/background, font, size, spacing and line-measure controls for 1.4.8. `TransferDestination.tsx` provides a non-drag alternative to file drops (2.5.7); the destination node is a custom dropdown (`Dropdown.tsx`, a button opening a menu of radio items). `SavedPasswords.tsx`, `server/src/vault-proxy.ts` and `server/src/vault.ts` provide expiry warnings and idle-time extension bounded by the existing maximum lifetime (2.2.1, 2.2.6). User-provided media has no inferable equivalent text: Filedeck offers native playback and a titled PDF frame but cannot supply captions/descriptions for arbitrary content.
- `styles.css` and `accessibility.css`: the focus indicator is **one** ring in one colour, not a dual-colour one: a 2px solid outline in `--focus-ring` (dark navy in light, light blue in dark), or on toolbar buttons an inset 2px ring in the same colour (source; the browser check confirms the computed style in both themes). A shared rule asks for a 44 px minimum size, but it does not hold everywhere: the browser check measures six controls on the main view below 44 CSS px (the panel grip is 24 wide, the location button 28 high, the breadcrumb folder and separator buttons 24 to 39 wide), so "44 px targets, zero findings" was not true and is withdrawn (see 2.5.5). Selected rows are marked by a 4px bar on the leading edge, a tinted background and `aria-selected`; tiles by a 2px ring; toggles by a 3px underline. There are no checkbox or state icons and no "selected" text in the rows, so the earlier "checkbox/state icons and text" wording was not true; the mark does not rely on hue and the browser check confirms the bar and `aria-selected` in both themes. Short windows (for example 844x390) use the phone layout, and at 844x390 at least five rows are fully visible in the browser check.

## Scoped browser validation

`web/test/browser/acceptance.mjs` runs on every change under `web/` in CI (the `browser` job) and locally against any build; see `web/test/browser/README.md`. It drives the built app in Chromium with a deterministic fake API and makes these checks (all pass on `main` at the time of this update):

- File list semantics, focus return (after Shift+F10 then Escape, rename, create and a toolbar menu), the 1366x768 context menu, panel Tab order and Alt+PageDown/Alt+PageUp, Trash keyboard selection, the shortcuts dialog and its focus trap, Properties tabs and chmod, worktrees and the pull request diff section, URL history and direct links, folder history, archive and sync routes, presentation settings, copy/move to another node and saved-password renewal.
- A 20,000-entry listing (small DOM, End and Home), at least five rows at 844x390, no horizontal document overflow at seven window sizes, and unsaved editor text surviving a resize across the panel-width and phone thresholds.
- axe-core with the `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa` and `wcag22aa` tags on the main view, an open context menu, an open dialog, Settings, Trash, Compare, the Markdown preview and the phone layout, each in light and dark: no violations.
- Measurements at 1365, 390 and 320 CSS pixels in light and dark (axe-core again, clipping, WCAG text-spacing overrides, first-Tab-stop focus visibility, document overflow) and a theme-token check (contrast of the boundary, ring, selection mark and muted text; single focus ring; selection mark).

Known defects the script still reports (not hidden: the checks keep running, and the run fails when one is fixed until its entry is removed): the 320 px breadcrumb target spacing (2.5.8, above); Properties opened from a breadcrumb folder is not kept in the URL, so a reload shows the selected file instead (navigation state must live in the URL). Reported without failing the run (levels the product does not claim): 7:1 text contrast of the selected row in dark (1.4.6) and the six sub-44 px targets (2.5.5).

### Still unverified

These are outside every check above and no statement in this document covers them:

- Real screen readers (NVDA, JAWS, VoiceOver, TalkBack) and speech or switch input.
- Real phones and tablets, including touch target use, rotation and on-screen keyboards.
- Real browser zoom (including 400%) and text-only zoom; pinch zoom on a device.
- Forced-colours mode beyond what a reading of the CSS shows: the `@media (forced-colors: active)` rules were not exercised in a browser.
- Firefox and Safari (the checks run in Chromium only).
- Deployment theme overrides, arbitrary custom foreground/background combinations, other node configurations, and arbitrary user-provided media and documents.
- Routes and states not listed above (editor, compare toolbar, sidebar tree, address bar popups, error states).

WCAG 2.2 removes 4.1.1 Parsing; it is not a success criterion in this matrix. No AAA conformance claim is made.
